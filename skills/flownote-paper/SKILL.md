# flownote-paper：把陌生概念长成解释模型

让一个不懂该领域、但愿意思考的人，不只知道论文说了什么，还能指出自己原先缺少哪些概念、这些概念怎样共同生成现象，以及什么条件变化会让模型失效。

全文围绕清楚的问题展开，保留不可省略的研究主线及其联系，不把多个独立发现压成一个中心实验。默认读者不熟悉行业对象与工作方式；用户指定背景时以其为准，让具体对象和动作持续承担解释。

论文有统一机制时，用它解释不同发现并检验条件变化；没有统一解释时，如实说明各项发现、证据和未解决的问题，不强造因果链。

## 理解契约

「见过术语」不等于「已经有这个概念」。若读者不能完成下面任一件事，就把它记入概念缺口：

- 用普通话指出它区分了什么，以及它不是什么；
- 说明它依赖什么、影响什么，和相邻概念怎样连接；
- 在论文案例中认出它，并判断一个反例或边界案例为何不同；

前三项检验单个概念是否形成；概念接成模型后，再检验关键条件变化时现象会怎样变化。概念缺口不是术语表。只记录中心命题、机制和证据链上的全部承重概念；外围术语按需解释，不让清单淹没论文思想。

## 三重成品合同

- **论文身份可辨认**：读者能指出研究对象、旧方法或旧解释看不见什么、作者实际造出了什么产物或关系、它怎样运行，以及最强证据边界。
- **认识确实更新**：读者能说出自己原来怎样理解，哪条论文证据迫使旧理解改变，新关系又怎样改变判断或行动。
- **解释可以重建**：有统一机制时，读者能用它解释不同发现、区分邻近案例并推想条件变化；没有统一解释时，能说清各项发现的联系与未知。预测不冒充已验证结论。

三项互不补分。案例顺畅不能替代论文身份，论文信息齐全不能替代认识更新，术语和实验清单也不能替代解释重建。

## Workflow Routing

这是一个 **conversation-first、no-save** 的认知方法，不是阅读生命周期或笔记写入流程。`ReadingGuide.md` 与 `references/template.md` 从当前 SKILL.md 所在目录读取。普通概念困惑交给 `flownote-think`，一般阅读整理交给 `flownote-read`。只有 `flownote-read` 明确委派、用户明确点名 `flownote-paper`，或用户提供论文并要求构建包含承重概念与失效条件的解释模型时才运行。

| 输入 | 必读 | 输出 |
|---|---|---|
| arXiv、PDF、paper URL、本地论文 | `ReadingGuide.md` 与 `references/template.md` | 在对话中返回 Markdown 解释草稿 |
| 只有论文标题 | 找到可靠原文后读 `ReadingGuide.md` 与 `references/template.md` | 在对话中返回 Markdown 解释草稿 |
| `flownote-read` 委派的论文模型任务 | `ReadingGuide.md` 与 `references/template.md` | 将解释草稿返回 `flownote-read` |

本技能不选择保存位置、不创建文件、不更新阅读进度，也不修改知识库状态。若用户随后要求保存，把草稿返回 `flownote-read`，由它确认后按既有写回规则处理。

## Gotchas

- *来源字段不是参考资料列表。* 只保留一个最接近论文原文的规范 URL，直接写裸 URL；不加链接描述，不并列摘要页、PDF 页或其他入口。
- *压出中心命题太早，会把未知概念藏进一句漂亮话。* 先写暂定命题，再扫描其中每个承重词；概念补齐后必须重写命题。
- *具体案例不能替论文换身份证。* 案例只负责降低进入门槛；最迟读完「它到底在解决什么」，读者应已知道研究对象、旧缺口和作者产物。
- *作者的产物必须可辨认。* 方法、理论关系、评测、资源或系统不是背景标签；要说明作者实际增加了什么可运行对象、作用关系、判断尺子或可行范围。
- *数字没有实验坐标就只是噪声。* 引用结果前先交代它在问什么、固定什么、改变什么、和谁比较；结果后立刻说明它改变了什么判断、还不能推出什么。
- *熟悉感最容易冒充理解。* 能翻译术语、复述定义或举一个相似例子，都不等于拥有概念；单个概念要经得起区别、关系和案例检查，整体模型还要经得起条件变化检查。
- *概念清单也会制造碎片。* 不按论文出现顺序或字母顺序罗列；按依赖关系补概念，并立刻接回当前研究问题。
- *定义不是概念。* 每个概念都要在至少一条关系和一个具体案例中工作；孤立释义默认删除。
- *模型不是流程图的别名。* 有统一机制时才检验它对不同发现及条件变化的解释力；并列发现不强造共同机制。
- *并非每篇论文都在反对旧观念。* 评测、数据集和工具论文常常只是暴露旧尺子的盲点；不要硬造稻草人。
- *评测贡献不等于科学发现。* 新 benchmark 让某个问题变得可测，不等于解释了现实世界。
- *证据和适用范围必须贴着主张。* 独立实验摘要和独立免责声明都会切断它们与洞见的关系。
- *不要默认 prose 就是最清楚的解释。* 架构、因果链、分布、权衡和状态变化若难以在脑中成形，应让关系直接显形。
- *图也会夸大论文。* 图必须与它所解释的证据和边界相邻；不能把「在这些条件下显示」画成普遍规律。
- *不要把公式删除当成通俗。* 若一个关系式就是核心洞见的最短表达，保留一个最小公式并立刻翻译成人话；应删除的是未解释的公式堆。
- *启发不是应用清单。* 优先只留一个判断问题，最多展开两个真正相关的用法。
- *允许思想含量有限。* 工程增量就说是工程增量；没有直接用途时不要硬编。

## 概念缺口到解释模型

先围绕暂定中心命题建立内部的「概念缺口账本」。对每个承重概念写下：它区分什么、它与谁发生什么关系、论文中哪个案例让它可见。按依赖顺序补：先补后续概念所依赖的，再补论文新增或改写的。

成文时，在「它真正看见了什么」中保留全部尚需补齐的承重概念，但按关系链推进：概念只在模型需要它的那一刻出现，并立刻回到案例。不要给每个概念分配一张卡或一个固定段落；全文合起来完成所有概念的「区别 + 关系 + 案例」，也不输出已经熟悉且不承重的词。

概念补齐后，若论文支持统一机制，把它们接成最小解释模型：

```text
条件/输入 -> 概念之间的作用关系 -> 首个可观察变化 -> 现象/结果
```

有统一机制时检查以下三项；没有时说明各项发现怎样互补或限制、哪些仍未知：

1. **回到原现象**：能解释原锚点及另一项不同发现，而不只是换词复述；
2. **区分邻近情况**：能说明一个看似相同的案例为何会有不同结果；
3. **改变一个条件**：能预测某个概念变强、变弱或缺席时，首先会观察到什么变化。

随后找出最大的剩余阻力：读者可能仍无法在脑中形成关系，也可能无法判断证据究竟支持模型到哪一步。选择理解成本最低的表征，不要默认继续写 prose。

| 论文中的思想形状 | 优先表征 |
|---|---|
| 模型架构、数据流、模块关系 | 结构图或流程图 |
| 因果链、训练过程、状态变化 | 因果图或时间轴 |
| 反馈、迭代更新、自我强化 | 回路图 |
| 分布、尺度效应、边际变化 | ASCII 曲线 |
| 准确率与成本、速度与质量 | trade-off 曲线 |
| 旧指标与新指标反复对照 | 小表格或二维矩阵 |
| 一个案例如何逐步变化 | 对齐的 example trace |
| 公式就是不可替代的核心关系 | 一个最小公式，加人话翻译 |
| 两三句话已经足够 | 纯文字 |

图不是标配。它只在降低理解成本时出现，并放在概念已经用人话和案例落地之后；图负责让关系显形，不替代概念形成。相关证据和适用边界紧随其后。ASCII 图使用 Markdown 的 fenced code block，宽度不超过 80 字符。

判断图是否有用，不只看它能否复述模型，还要看它是否守住证据分寸：读者只看图，应能说出哪些概念在怎样作用、论文改变了什么判断，但不会得到超出实验支持的结论。若图只是把摘要换行，删除它。

## Quick Reference

1. 判主类型并锁定论文身份：研究对象、旧缺口、作者产物、运行关系与最强边界。
2. 从外行能看见的具体困惑进入；必要时换案例并说明它补充什么，不让案例替代论文身份。
3. 写暂定命题脊柱：「面对什么；看见什么；以后怎么判断。」
4. 扫描命题、机制和证据链，记下全部承重的概念缺口。
5. 按依赖顺序，用区别、关系和案例补齐概念，再重写中心命题。
6. 有统一机制时连接概念并检查解释力；没有时保留独立发现和未知，不强造模型。
7. 给每条承重关系找到证据或明确标为作者解释 / 结构推演；中心实验同时写清问题、固定项、变化项、比较者、结果意义与边界。
8. 依次写问题、洞见、带走，最后压出速读。

使用以下 Markdown headings：

1. `# 速读`
2. `# 它到底在解决什么`
3. `# 它真正看见了什么`
4. `# 我能带走什么`

## Examples

**评测论文**

不要把「给科研想法加谱系评测」说成「科学想法真的像基因一样演化」。先发现读者对「机制继承」可能只有词感，没有概念：它不是主题相似，而是后一个方案接住并改动了前一个方案的作用关系。再用父子 proposal 的具体差异让这个概念工作，最后建立「继承关系怎样被新评测看见」的测量模型。

**方法论文**

不要停在「提出新模型并提升指标」。若论文在训练模型判断何时收尾，先补「收尾反馈」：它不是推理能力，而是系统根据当前答案状态决定继续计算是否仍有收益。把它与「更强推理」放进同一个案例比较，模型才会解释为什么答案已经正确，token 仍继续增长。

## Completion

返回解释草稿前确认：

- 草稿使用 Markdown，frontmatter 完整；没有创建或修改任何文件。
- `source` 只有一个裸 URL，没有描述文字或并列链接。
- 顶层只有四个规定章节。
- 读完前两个章节能回答研究对象、旧缺口和作者产物；答案不能无差别套到邻近论文。
- 中心命题不是论文标题、模型名或贡献清单。
- 案例持续支撑问题与发现；更换案例时交代对应关系及必要性。
- 已扫描中心命题、机制和证据链；所有尚未形成的承重概念都被记录，外围术语没有混入清单。
- 每个被记录的概念都在区别、关系和案例中工作，而不是只有释义或类比。
- 统一机制能解释不同发现并检验条件变化；没有统一机制时，必要主线及其证据边界仍完整。
- 每条承重关系都有相邻的证据，或被明确标为作者解释 / 结构推演；没有为了凑数堆实验。
- 中心实验有完整坐标：在问什么、固定什么、改变什么、和谁比较、结果改变什么判断以及不能推出什么。
- 证据、主张和适用边界彼此相邻，没有拆成实验摘要与独立免责声明。
- 已完成关系阻力与证据阻力扫描；解释模型若具有结构、形状或动态关系，没有只靠文字带过。
- 图表若存在，只看图能复述概念关系与判断变化，却不会得出超过证据的结论；ASCII 图格式与宽度合格。
- 若没有图表，短句确实已经是成本最低的表征。
- 主文没有未解释的 LaTeX 公式或旧模板章节；若保留最小公式，紧接着有人话翻译。
- 速读说明问题、发现和判断变化的联系；并列发现不被强写成因果链。
- 只读速读能回答「为什么需要这篇、它多看见了什么、以后怎样判断」；读完正文还能回答「我原先缺哪几个概念、它们怎样共同解释现象」。
