# 速读

{最后再写。用一个短段落交代：研究对象面对什么旧缺口、作者造出了什么产物或关系、它建立了什么解释模型、我以后怎样判断。只压缩一次，不逐句复制正文。}

# 它到底在解决什么

{从一个具体困惑、失败或反常结果开场。必要时换案例以保留不同研究主线，并说明联系。}

{说清人们原来怎么处理，以及这种处理为什么在这里失灵。指出旧理解缺少了哪个关键区分，但先不展开论文答案。讲到读者开始期待新模型就停。}

{本节结束前让论文身份可辨认：研究对象、旧缺口、作者产物，以及产物从输入到输出的关键作用关系。不要写贡献清单，让这些信息沿当前困惑自然出现。}

# 它真正看见了什么

{先用一句人话说出新判断，再沿模型的关系链推进。概念只在下一步关系需要它时出现，并立刻回到对应的具体案例，让读者看见它区分什么、怎样起作用。全文覆盖概念缺口账本中的全部承重概念，但不要逐概念写卡片或固定段落，也不要收录不承重的陌生词。}

{论文有统一机制时，把这些概念接成最小解释模型：条件或输入怎样改变概念间的作用，首先出现什么可观察变化，最后为何生成锚点中的结果。再用一个邻近情况或一个关键条件变化，展示模型会预测什么不同，并区分验证与推演。没有统一解释时说明各项发现的关系和未知，不强造因果链。}

{扫描关系阻力与证据阻力。若文字不足，在概念已经落地后加入成本最低的表征：结构图、流程图、曲线、小表格、example trace 或一个带人话翻译的最小公式；短句足够则不加。ASCII 图使用 Markdown fenced code block，宽度不超过 80 字符。}

{让证据紧跟它支持的关系。按是否改变判断、限制结论或解释例外选择结果，不设数字配额；若模型有更多承重关系，确保每条关系都有证据，或明确标为作者解释 / 结构推演。用准确动词校准分量。}

{中心实验出现时先交代它在问什么、固定什么、改变什么、和谁比较；结果后立即说明它改变了什么判断、还不能推出什么。}

{区分论文直接测到的关系、作者给出的解释与为了理解而做的结构推演。若存在真实误用风险，在相应关系后就地说明它最多证明什么、尚未证明什么或只在哪些条件下成立。不要另起免责声明。}
