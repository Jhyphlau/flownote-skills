# 想法批量整理助手

目标：把“每日回顾没来得及处理的记录”批量清掉，避免长期堆积。

## 启动即执行

1. 扫描 `01-捕获层/每日笔记/`（默认最近 7 天，可由用户指定范围）。
   候选仅来自记录章节的个人想法、疑问、灵感与感受；任务进展不列入。旧标题按语义识别，旧记录中明确的执行流水跳过、不搬移，不能仅因无处理标记就送去制卡。
2. 优先提取已标记 `⏭️ 待 /flownote-inbox` 的记录。
3. 再提取未处理记录（无 `→`、无 `✅`、无 `⏭️` 标记）。

## 流程锁定规则（高优先级）

- 用户在处理中提到“阅读/项目/复盘”等词，默认视为当前记录输入，不自动切换技能。
- 仅在两种情况允许切换：
  - 用户明确输入其他命令（如 `/flownote-card`）
  - 用户明确要求停止本轮整理
- 流程完成标志：候选记录已处理或明确延期，且输出汇总。

## 重要提醒

- 禁止使用示例数据，所有处理必须基于真实日记内容。
- `flownote-inbox` 的核心对象是“残留记录”，不是重做当日完整回顾。
- 对既有想法只追加去向标记、保留原时间。用户另行要求新增想法时，读取 `../flownote-capture/references/write-update-rules.md` 并满足时间戳要求；不为旧条目批量补造时间。
- 转永久笔记必须调用 `flownote-card`，不直接套模板生成。

## 主流程

1. 扫描并展示候选（按“延期优先”排序）。
2. 逐条或批量决策去向。
3. 回写日记标记。
4. 输出批量结果与剩余待处理数。

## 去向决策（确定性）

每条记录仅能选一种：

1. 转永久笔记（调用 `flownote-card`）
2. 转任务（写入任务区）
3. 标记已处理（保留记录）
4. 继续延期（保留 `⏭️ 待 /flownote-inbox`）

## 回写标记规范

- 转永久笔记：`→ [[笔记名]]`
- 转任务：`→ 任务`
- 已处理：`✅ 已处理`
- 延期：`⏭️ 待 /flownote-inbox`

## 输出标准

- 必须输出：总候选数、四类去向数量、剩余延期数量。
- 必须包含：新建永久笔记列表（如有）与新增任务列表（如有）。
- 有未处理残留时，明确提示下次继续使用 `/flownote-inbox`。

## 检查清单

- [ ] 已扫描并提取候选记录
- [ ] 已完成去向决策并回写标记
- [ ] 已调用 `flownote-card` 处理高价值记录（如有）
- [ ] 已输出批量处理汇总

## 渐进加载（按需读取）

- 扫描与路由规则：`references/workflow-and-routing-rules.md`
- 汇报与确认模板：`references/output-templates.md`

## 相关技能

- `flownote-review`：每日回顾后将残留记录移交 inbox
- `flownote-card`：将高价值记录转为永久笔记
- `flownote-week`：周回顾时复核仍未处理的残留记录
