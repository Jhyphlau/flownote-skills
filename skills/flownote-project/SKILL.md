# 项目入口与持续管理

目标：让用户知道项目为什么做、确认到哪里、下一步如何服务目标，以及在等什么。用户决定顺序；没有必要动作可以暂不推进。源项目保留执行事实，FLOWnote 维护有来源时间的摘要。

## 先按请求选分支

- **查看/恢复**：读取并在对话中回答；不写项目页、日记或 STATUS，不执行工程工作。没有入口也只指出缺口，不自动立项。
- **更新摘要**：用户明确要求时，按下述核源流程更新选定入口。授权只覆盖本次指定范围，后续查看仍只读。
- **新建/接入**：明确要求才执行下文立项流程。外部项目复用已有目标和事实指针，只询问会改变范围的缺失信息；一个仓库可以对应不同目标范围，先检查是否已有相同入口。

## 查看与更新：按需核源

1. 读取选定项目主页及其实际指向、当前可访问的源记录。项目执行事实以相应源项目已确认的记录为准；只有用户提供了跨项目汇总且可核验其来源时，才将其作为汇总结论的来源，并保留与单项目事实的区别。来源不存在或权限不足时标明未核验。不是读取整个仓库或全部 Session；不拉取远端、改源仓或为刷新催提交。
2. 读取主页保留的 Owner 行动来源，以及最近核验以来相关日记/回顾。复用现有反馈，不让用户重述背景或填第二份日报。先保留旧的未完行动，再逐项根据明确完成/取消证据更新；新摘要未提到不算完成。区分同名事项的阶段，设计完成不等于实施验收，commit 不等于 push/发布。
3. 返回：目标、已确认进度、下一步及其服务目标的理由、等待事项、来源和截至时间。Agent 建议与已确认行动分开；用户的审阅、决定等本地行动可来自其提供的日记或任务记录，但不能冒充源项目工程完成。同一行动只保留一个维护来源，项目摘要链接已有权威入口，不另列一份独立待办。
4. 源不可达时保留旧摘要和旧的来源截至时间，标注“本次未核验”；其他可读项目继续。差异先回查来源范围与时间；明确的旧快照不覆盖新源事实。无法消解时保留双方指针，向原维护者提出核实需要，不擅改源状态、组合结论或让 Owner 手工对账。联系其他任务沿既有通信授权，不自动派工。
5. 查看分支到此结束，报告零写入。更新分支只修改事实摘要和已确认行动引用，保留用户思考、历史证据及无关内容；复读后按 `flownote-memory` 的 source-first / STATUS-last 整合增量指针。源完全不可达时不推进来源日期，不把刷新尝试当新事实。

## 摘要与展示合同

项目页正文保留目标、检查点依据、下一步意义、等待/Owner 行动及来源链接。Home 使用同页 frontmatter：`状态`、`首页显示`、`阶段`、`下一步`、`来源截至`。下一步只维护一份短句，正文补理由或链接原任务，不另造一张可独立勾选的执行清单。

`来源截至` 是摘要所依据的事实日期，可用短文本说明多来源日期；`核验日期` 另记 Agent 本次查阅日期。不能用今天核验洗新旧事实。只有 Owner 选定项目才设 `首页显示: true`，不为显示而更改项目真实状态。尚未核验的来源写明未知，不假装实时。

用户明确选“今天做”后才交给既有 `flownote-note`，保留原行动链接；未选入今天的行动继续留在原来源。本技能不修改日周回顾流程，不自行维护日记中的第二份任务。

## 以下仅适用于新建/接入

外部项目使用模板中的可选摘要区，不复制源计划/工作日志。先采用已有所属领域；接入不授权工程执行、同步候选、知识晋升或模板发布。

## 启动即执行

1. 读取项目目录：`04-创造层/项目/`。
2. 读取项目总览：`04-创造层/项目/📍 项目总览.md`（若存在）。
3. 收集项目输入：名称、目标、截止日期、优先级、所属领域。

## 流程锁定规则（高优先级）

- 用户在回答中提到“阅读/笔记/回顾”等词，默认视为项目信息输入，不自动切技能。
- 仅在两种情况允许切换：
  - 用户明确输入其他命令（如 `/flownote-read`）
  - 用户明确要求停止本次项目创建
- 流程完成标志：项目目录已创建 + 项目主页已写入 + 领域页已同步。

## 重要提醒

- 禁止使用示例数据；项目编号与名称必须来自真实目录扫描与用户输入。
- 项目编号必须先扫描后分配，禁止猜测“下一个编号”。
- 路径操作前先确认目标目录存在；不存在先创建。
- 涉及多领域时可多点关联，但项目主页路径唯一。

## 触发机制

- 主动触发：用户输入“新建项目 / 启动项目 / 立项”。
- 路由触发：从 flownote 入口或周/月回顾中识别需要新开项目。

## 主流程

1. 阶段一：收集并确认项目信息。
2. 阶段二：扫描现有编号并确定新编号。
3. 阶段三：创建项目目录并生成项目主页。
4. 阶段四：更新项目总览与所属领域页关联。
5. 阶段五：输出创建结果与下一步建议。

## 关键执行规则（确定性）

- 编号格式需沿用当前知识库的实际样式（先扫描再决定，如 `26-01 项目名`）。
- 年份规则：同年内序号递增；跨年后从 `01` 重新开始。
- 项目主页模板：`assets/项目模板.md`。
- 项目主页路径：`04-创造层/项目/{{编号}} {{项目名称}}/📍 项目总览.md`。
- 主页必须包含基础字段：编号、目标、领域、优先级。
- 主页须提供项目文件目录与最近更新。Dataview 已启用时使用模板中的两个查询面板；未启用时改用已核实文件的普通 Markdown 链接列表，修改时间不可得就标明最近更新未核验，不安装插件或虚构排序。
- 领域页路径固定：
  - `03-连接层/🌱 内容创作.md`
  - `03-连接层/🌱 产品开发.md`
  - `03-连接层/🌱 个人成长.md`
  - `03-连接层/🌱 效率工具.md`
- 若 `04-创造层/项目/📍 项目总览.md` 不存在，先创建最小索引结构再写入项目条目。
- 若无匹配领域页，先与用户确认是否新建，再从本文件所在目录的上一级（共同 skills 根）读取 `flownote-init/references/领域页模板.md` 创建并写入首个关联项目。

## 快速立项模式

触发：用户只想先开项目框架，细节稍后补。

最小交付：

1. 确定项目名称与所属领域（最低必填）。
2. 完成编号分配与目录创建。
3. 生成基础项目主页。
4. 更新项目总览与领域页。

## 输出标准

- 必须输出：
  - 新项目编号与完整路径
  - 已创建文件列表
  - 已更新的领域页列表
  - 下一步建议（完善成功标准/行动计划/支撑知识）
- 输出必须可追溯，包含可点击路径。
