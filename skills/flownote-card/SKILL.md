# 永久笔记制作引导技能

目标：严格按卢曼卡片笔记法制卡，确保"用自己的话表达 + 一卡一事 + 高质量连接"。

---

## 第一步：输入源判定与分流

启动后立即执行：

1. 读取 `Meta/.ai-memory/STATUS.md` 检查待制卡事项。
2. 分析用户输入，判定输入源类型。
3. 按判定结果分流到对应路径。

### 判定规则

| 输入源 | 判定特征 | 分流路径 |
|--------|----------|----------|
| **收藏文章** | 篇幅较长、结构完整（有标题/段落/论述）；内容非用户原创（他人文章风格）；用户未附带自己的观点 | → 路径 A |
| **文献笔记** | 来自 `02-培养层/文献笔记/` 的文件；由 `flownote-read` 产出；包含已提取的洞见条目 | → 路径 B |
| **用户笔记** | 来自每日记录、回顾思考、inbox 整理等；内容是用户自己的零散想法或记录 | → 路径 C |

判定优先级：先识别混合来源的项目候选，按下节处理；其余先检查文献笔记，再检查收藏文章。仅明确为用户自己的记录才进入路径 C；归属不明且影响制卡时，只澄清该归属，不默认视为用户观点。

用户也可以主动声明来源（如"这是我收藏的一篇文章"），以声明为准。

### 混合来源项目候选接入

- 读取用户实际提供或选定的候选及其明确指向的理解记录，区分项目事实、Agent 判断和用户原话；用户认可候选的去向，不代表认领材料中的全部观点，冻结也不等于内容已证实。没有可核验来源时说明缺口，不凭本机约定猜测记录。
- 复用可核验记录中的用户理解、例子、边界与去向决定，直接按共享深度标准检查。已明确的内容不重问，不重新判定已有去向；只补当前制卡真正缺失的理解。
- 进入下方共享制卡流程，不把整份混合材料套入路径 C。保留各自归属，Agent 的补充不得改写成用户观点。每张卡片的标题、正文与关联仍须用户确认，既有去向决定不替代本次发布确认。
- 成稿以用户已表达的理解及已记录的收窄为依据，标题、理由和做法均保持同一适用范围。项目当时的取舍若需保留，作为有归属的项目例子呈现；不能提升为通用主张后仅在边界段落补免责声明。来源中的“本轮”“尚未写入”等状态按原日期说明，不搬成新卡当前状态。
- 来源链接指向实际材料；冻结快照只读，不另建来源登记表或文献笔记中转。保存时读取 `references/workflow-and-sync-rules.md` 的只读来源规则。

## 路径 A：收藏文章 → 思考引导 → 多卡产出

详细规则：`references/article-to-cards-guide.md`

核心理念：文章是思考的触发器，不是笔记的内容来源。卡片记录的是用户自己的思考。

**流程概览（4 阶段）：**

1. **文章解析与思考方向推荐** — 提取核心论点，推荐 3-6 个思考方向，用户选择或自定义。
2. **逐方向引导思考** — 每个方向通过引导问题帮用户形成自己的观点，无法展开的方向可跳过。
3. **卡片规划与确认** — 汇总思考结果，规划卡片列表（断言式标题草案），用户确认增减。
4. **逐张制卡** — 按确认列表逐张进入共享制卡流程（深度闸门 → 成稿 → 关联 → 保存）。

---

## 路径 B：文献笔记 → 洞见提取 → 制卡

详细规则：`references/literature-note-cards-guide.md`

核心理念：文献笔记已经过 `flownote-read` 整理，包含结构化的洞见条目，制卡聚焦于将洞见转化为用户自己的永久笔记。

**流程概览（3 阶段）：**

1. **洞见扫描与候选提取** — 读取文献笔记，提取已标记的洞见条目，列出候选，用户选择要制卡的洞见。
2. **逐条深度判定与补充** — 对每条候选进入深度充足性闸门，不足则引导补充。
3. **逐张制卡** — 进入共享制卡流程，来源链接到对应文献笔记。

---

## 路径 C：用户笔记 → 提炼 → 制卡

详细规则：`references/user-note-cards-guide.md`

核心理念：用户的零散记录中蕴含值得沉淀的想法，帮助用户识别并提炼出可制卡的观点。

**流程概览（3 阶段）：**

1. **内容扫描与观点识别** — 阅读用户的记录内容，识别出可独立成卡的观点或想法，列出候选。
2. **逐条深度判定与补充** — 对每条候选进入深度充足性闸门，不足则引导补充。
3. **逐张制卡** — 进入共享制卡流程，来源标注为每日记录或对应笔记。

---

## 共享规则（所有路径通用）

以下规则适用于所有路径的制卡环节，详细规则见对应的 references 文件。

### 深度充足性闸门

每张候选卡片必须先过闸门，检查三项：

1. 观点是否明确（不是模糊话题）
2. 是否解释了"为什么成立"
3. 是否给出边界/条件/场景中的至少一项

判定：>= 2 项满足 → 可制卡；< 2 项 → 深度不足，先引导再制卡。

深度不足时：告知不足点 → 调用 `/flownote-think` 引导 → 收集补充后重新判定。

### 用户原话优先（硬约束）

- 标题、核心观点、正文、应用场景均优先使用用户原话。
- 若内容缺失，标记"待用户补充"，禁止 AI 自动补写完整段落。
- AI 可做的仅限：结构重排、重复合并、语义澄清提问。

### 制卡步骤

1. 断言式标题（完整陈述句，表达明确观点）
2. 核心观点（一句话概括）
3. 详细说明（为什么成立 + 具体实现 + 边界与适用条件）
4. 关联发现（分层读取）
5. 用户确认后保存至 `02-培养层/永久笔记/{{标题}}.md`
6. 按共享同步规则更新主题笔记与关联；只读来源仅引用、不回写
7. 输出结果汇总

### 关联发现规则（分层读取）

按顺序执行，禁止全量扫描：

1. 读取主题笔记标题（`02-培养层/主题笔记/`）
2. 读取领域页标题（`03-连接层/`）
3. 选择 1-3 个候选主题/领域
4. 定向读取主题笔记，提取已链接笔记标题
5. 定向读取候选笔记内容，确认关联关系

### 流程锁定规则

- 制卡过程中提到"阅读/项目/回顾"等词，默认视为当前制卡输入，不自动切技能。
- 仅在用户明确输入其他命令（如 `/flownote-read`）或明确要求停止时才允许切换。
- 流程完成标志：卡片保存完成 + 关联更新完成 + 已输出汇总。

### 重要提醒

- 禁止使用示例数据，所有内容必须来自用户真实输入与真实文件。
- 禁止 AI 代写用户观点。
- 未经用户确认，不写入争议链接或猜测性结论。

---

## 输出标准

- 必须输出：新建卡片、关联关系、主题笔记更新及来源/反向链接处理结果；只读来源明确标注“仅引用，未修改”。
- 每条更新标注具体路径，确保可追溯。
- 有待确认项时明确标记"待确认"，不静默落盘。
