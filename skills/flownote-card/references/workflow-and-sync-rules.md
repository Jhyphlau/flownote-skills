# 共享制卡与同步规则

本文件定义所有路径共享的制卡步骤和同步规则。收藏文章、文献笔记、用户笔记完成前置阶段后，以及混合来源的项目候选完成内容归属核对后，统一遵循本规则。

---

## 1) 深度充足性判定

每条候选在制卡前必须检查三项：

1. 观点是否明确（不是模糊话题）
2. 是否解释"为什么成立"
3. 是否提供边界/条件/场景（至少一项）

判定：

- >= 2 项满足 → 可制卡
- < 2 项满足 → 深度不足，先引导

## 2) 深度不足处理

当深度不足时，必须执行：

1. 告知不足点（具体到缺失维度）
2. 调用 `/flownote-think` 进行深度引导
3. 收集用户补充后重新判定
4. 通过后继续制卡

示例提示：

`当前内容观点清楚，但缺少成立条件与适用边界。先用 /flownote-think 做一轮深挖，再继续制卡。`

## 3) 制卡步骤

1. 标题：断言式完整句
2. 核心观点：一句话
3. 详细说明：200-400 字（为什么成立 + 具体实现 + 边界与适用条件）
4. 关联关系：2-3 条（支持/反对/补充）
5. 用户确认：标题、正文、关联

## 4) 用户原话约束

- 标题和正文尽量使用用户原话
- AI 不得编造新观点或新例子补全卡片
- 若信息不够，写"待用户补充"，不自动补写

## 5) 关联发现（分层读取，禁止全量扫描）

按顺序执行：

1. 读取主题笔记标题（`02-培养层/主题笔记/` 文件夹）
2. 读取领域页标题（`03-连接层/`）
3. 选择与当前候选最相关的 1-3 个主题/领域
4. 读取这些主题笔记内容，提取其中现有链接笔记标题
5. 再读取候选笔记正文，确认能否建立关联
6. 输出建议关联并说明关系类型

禁止：

- 一开始遍历并读取所有永久笔记
- 未验证正文就直接建立关联

## 6) 保存与同步顺序（不可打乱）

1. 保存永久笔记至 `02-培养层/永久笔记/{{标题}}.md`
2. 更新主题笔记（在相关主题笔记中添加链接）
3. 更新可编辑的来源笔记（先遵循下方只读例外，再按各路径 guide 处理）
4. 更新可编辑笔记的反向链接；只读来源由卡片中的来源链接建立关联
5. 输出汇总

汇总前复读本次写入的卡片及关联位置，按实际内容报告保存、链接与来源处理结果；已写入的 wikilink 即为已建立的链接，不因旁注“待确认”就报告为未建立。

### 只读来源例外（优先于各路径 guide 的回写要求）

- `00-Inbox/` 已有原始素材及用户提供的冻结项目来源快照保持只读，不追加反向链接、回填字段或改写原文。
- 卡片引用实际来源文件，并保留已有的具体段落或版本定位。Obsidian 可通过卡片的来源链接发现反向引用，无需修改来源；主题关联仍使用既有分层读取规则。
- 汇总标注“来源仅引用，未修改（只读）”；这是预期处理，不是同步失败。普通可编辑来源仍按下列 A/B/C 规则更新。

### 来源笔记更新（按路径区分，仅限可编辑来源）

- **路径 A（收藏文章）**：若已存为文献笔记，按路径 B 处理；若未存，标注"收藏文章：《文章标题》"
- **路径 B（文献笔记）**：两处更新 — ① 「本书衍生的永久笔记」区块追加链接 ② 洞见条目的 `永久笔记:` 字段回填
- **路径 C（用户笔记）**：在来源笔记中添加反向链接（如有明确来源文件）

## 7) 失败恢复

若任一步骤失败：

1. 报告失败位置
2. 停止后续写入
3. 修复后从失败步骤继续

禁止静默失败。
