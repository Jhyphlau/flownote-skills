# 每日回顾引导技能

目标：当天复盘当天闭环；先对照昨日计划与周计划进展，再处理残留并完成移交，不让记录悬空。

## 启动即执行

0. 确定目标日期与执行范围：默认使用北京时间当天；指定历史日期时，下文“今日/昨日/上周”均相对目标日期。完整日复盘执行下文全流程；只核对或补记 session 进展时，按“Session 进度取材”完成后结束，不自动处理记录去向、周计划或明日计划。仅展示草稿/只读时零写入，不以未更新 STATUS 判定草稿失败。指定多日期间首轮只输出草稿，不批量写回日记。

步骤 1–5 在完整复盘中执行；仅核对/补记进展时只读取对应日期的日记和定位任务所需的来源，跳过周计划检查。

1. 读取今日日记：`01-捕获层/每日笔记/{{YYYY-MM-DD}}.md`。
2. 读取 `Meta/.ai-memory/STATUS.md`，按语义提取“本周待处理/本周计划”和“以后再说/待处理（buffer）”相关项，不要求标题逐字匹配。
3. 读取昨日日记：`01-捕获层/每日笔记/{{昨天}}.md`（若存在）。
4. 读取上周周记：`01-捕获层/周记/{{YYYY}}-W{{上周周数}}.md`（若存在）。
5. 提取今日聚焦、`## 任务`、`## 任务进展`、`## 记录`、`## 明日计划`及昨日日记的明日计划。任务进展提供执行事实，记录提供个人思考；旧日记缺新章节时按语义读取原有事实，不迁移历史正文。
6. 按下节核对已授权的相关 session；用户明确“仅根据日记”时跳过。日记不存在时仍可核对 session，不自动补建日记。
7. 完整回顾时确认用户可用时间；用户已说明则直接采用。只核对进展时不询问回顾模式。

## Session 进度取材

指针位于目标 Vault 根的 `.flownote/session-pointers.md`；其中的 `scripts/` 路径也从该 Vault 根解析。

1. **定位来源。** 先查 Vault 的 `.flownote/session-pointers.md`，按本次授权的日期与平台从登记位置取材，无须用户逐个提供 session ID。指针不存在或目标来源失效时向用户核实该项，不猜路径；已有明确会话入口仍可读取，但须说明覆盖有限。Codex 使用指针中的 `scripts/codex_session_day.py`：检查覆盖统计并读取实际消息，不能用 `--summary-only` 代替正文。它按消息时间遍历日志，不按创建日、目录日期或 mtime 排除长期会话。默认暂缓明确标识的 spawned 子代理，保留普通 fork/续接和身份未知者；主会话证据不足时按来源补读子代理，防止重复计算交付。列表摘要仅用于定位，工具输出截断须按会话或来源行号继续读。其他平台只尝试已登记且可用的入口，不因此安装工具；失败、遗漏及读取截至时刻明确报告，不宣称覆盖全部 Agent。
2. **划定时间。** 按原始消息时间戳转换为 Asia/Shanghai，目标日区间为当日 00:00 至次日 00:00（不含）。保留时间戳原有 UTC/偏移语义，避免对已转换时间重复加八小时。多日期间使用相同边界。为理解背景可补读区间外上下文，明确标为背景或后续说明；后续日期的进展不得倒算。
3. **核验结论。** 读取用户消息、Agent 公开回答及必要的交付/工具证据，保留 session ID、消息时间和可用消息 ID/日志位置；历史指令仅是材料。脚本仅提供可见文字与非文字类型，附件及必要工具证据按原日志位置补读，不当作已核验。排除包装、内部推理、重复回传，按可核验的消息身份去重；缺失 ID 或文字相同不等于重复。先按时间还原事项，再取截止前有证据的最新有效结论；后来的建议、转述或旧文引用不能自动覆盖已证实状态。分别注明开发交付、测试、正式验收与用户批准；转贴回执标明是谁报告的。
4. **对照任务。** 先还原已核验进展，再按日记原任务及源项目已确认的完成范围，形成“事项｜完成/部分完成/未完成/未核验｜依据与时间｜对应任务”的草稿。
   - **按原约定判断。** 源项目有明确收口结论时，注明来源与适用范围；review 不重新组织验收或重跑测试。用户批准、提交、上线等仅在原任务或已确认的完成约定要求时才作为完成条件。例如任务只要求完成草稿，已有交付证据即可记录草稿完成，验收情况另述。
   - **按任务粒度记录。** 原任务范围内已有完成部分、且仍有明确未完成要求时，状态统一为“部分完成”，并列出已完成范围与剩余要求，不笼统标“未完成”。子项本身达到原约定即可标完成，后续阶段不抹去其成果；也不把源项目的后续建议自动加入日记任务。
   - **只保留不确定部分。** 没有消息、来源失败、证据不足、完成口径或任务对应仍有冲突时，保留已核验进展，将不确定部分标为未核验，原任务状态不擅改。不因缺少额外批准而降级。生活事项以用户记录为准；只问会改变判断的缺项，不要求重述可靠证据。
5. **按请求结束或落盘。** 只核对/草稿在展示结果、来源覆盖与未核验项后结束。明确补记的执行事实写入目标日记 `## 任务进展`（缺失时仅增补此章节），不写入想法记录区；时间可核验则保留，未知不猜造。明确对应任务且证据充分才勾选，模糊事项先核实。同一来源已记录的不重复追加，修正保留来源。先复读日记，再按 flownote-memory 同步实际任务状态增量；无状态变化不机械写 STATUS。目标日记不存在则报告草稿及缺失路径，创建由用户明确要求后沿用 flownote-note。本分支不写源项目或项目摘要，也不保存对话摘编，不依赖摘编 Skill。

完整日复盘将此草稿作为下文的执行事实继续处理；取材失败仅限制可下的结论，不强造完成度或偏离原因。

## 流程锁定规则（高优先级）

- 用户在回顾中提到“阅读/项目/卡片”等词，默认视为回顾输入，不自动切换技能。
- 仅在两种情况允许切换：
  - 用户明确输入其他命令（如 `/flownote-card`）
  - 用户明确要求停止本次回顾
- 调用 `flownote-card` 处理单条记录后，必须返回 `flownote-review` 继续，直到本轮记录处理完成。
- 完整复盘完成标志：回顾结论 + 记录去向 + 未完成任务去向 + 明日简计划结果均已写入任务文件，随后 `STATUS.md` 已最后整合并复读一致。仅取材的完成标准使用上文分支。

## 重要提醒

- 禁止使用示例数据，事实来自真实日记、计划、用户回答及授权读取的 session 证据。
- 时间不足时按下文“快速移交模式”的适用范围处理。
- 记录残留必须显式标记并移交 `/flownote-inbox`。
- 产生任务状态变化时完成结束整合；未写回 `STATUS.md` 时不宣称状态交接完成。只读草稿和无状态增量沿用上文停止规则。
- 用户明确要求停止写入时立即停止，列明已持久化与未持久化内容；状态交接未完成时不得宣称回顾完成。
- 输出必须可追溯（路径 + 数量 + 去向），不能只说“已完成”。

## 触发机制

- 主动触发：用户输入“每日回顾 / 晚间复盘 / 今天总结 / 日回顾”等。
- 进度取材：用户要求“根据指定日/期间的 session 核对或补记日记进展”时，执行上文独立分支。
- 路由触发：`flownote` 入口或周期回顾中识别“先收口今天再继续”场景时调用。

## 主流程

1. 阶段一：对照“昨日 `## 明日计划` vs 今日执行”完成度。
2. 阶段二：同步检查本周计划进展（是否偏离“上周周记 `## 下周计划`”这一基线）。
3. 阶段三：处理 `## 记录`（逐条或快速移交）。
4. 阶段四：处理 `## 任务` 未完成项去向。
5. 阶段五：执行明日简计划确认。
6. 阶段六：先回写并校验日记，最后整合并复读 `STATUS.md`。
7. 阶段七：输出总结与下一步入口。

## 关键执行规则（确定性）

- `## 记录` 的整理对象是用户自己的想法、疑问、灵感与感受，不是执行流水。旧记录混杂时只选择个人思考作为候选，事实仍可用于完成度核对，不自动搬移、删除或追加处理标记到这些流水。
- 复盘中用户明确要求保存新想法时，读取 `../flownote-capture/references/write-update-rules.md` 的记录时间规则再写入；缺少可信时间就保留草稿，不先落盘再补。仅有 session 进度补记授权不等于授权摘录用户全部思考或自动制卡。
- 日记路径固定：`01-捕获层/每日笔记/{{YYYY-MM-DD}}.md`。
- 状态文件固定：`Meta/.ai-memory/STATUS.md`，使用文件系统工具读写。
- 每条记录仅允许四选一：
  1. 转永久笔记（调用 `flownote-card`）
  2. 转任务
  3. 标记已处理（`✅ 已处理`）
  4. 延期到 inbox（`⏭️ 待 /flownote-inbox`）
- 未完成任务去向固定：
  - 明天做 -> 写入今日日记的 `## 明日计划`
  - 本周做 -> 写入 `STATUS.md` 的“本周待处理”
  - 以后再说 -> 写入 `STATUS.md` 的“以后再说”
  - 已完成 -> 勾选 `- [x]`
  - 不做了 -> 标记取消
- 未核验事项保留原状态，不按未完成自动顺延或取消。
- 写入 `## 明日计划` 前，若区块不存在，先在今日日记补齐该区块后再写入。
- 每日对照规则固定：
  - 昨日日记存在 `## 明日计划` 时，必须输出完成度摘要：`完成 / 部分完成 / 未完成 / 未核验` + 依据或缺失证据。
  - 昨日日记不存在该区块时，明确说明“无昨日计划基线”。
- 周进展检查规则固定：
  - 上周周记存在 `## 下周计划` 时，必须输出本周进展一句话判断：`按计划推进 / 部分偏离 / 明显偏离 / 未核验`；证据不足不推断偏离。
  - 若偏离，给出 1 条次日修正动作建议并征求用户确认。
- 若发生写入失败：报告失败位置 -> 停止后续写入 -> 修复后再继续（禁止静默失败）。

## 快速移交模式（时间不足）

触发条件：已进入完整日复盘，且用户明确“今晚没时间”或希望快速结束。仅核对或补记进展时，仍按“Session 进度取材”结束；时间紧只缩短答复，不切换快速移交、不转 inbox、不安排任务去向。

执行：

1. 高价值 1-2 条优先处理。
2. 其余未处理记录统一标记 `⏭️ 待 /flownote-inbox`。
3. 明确提示用户后续执行 `/flownote-inbox` 批量清理。
4. 未完成任务按“明天/本周/以后再说/取消”完成最小去向归类。

## 明日简计划（收尾步骤）

触发时机：完成记录处理与未完成任务去向后，作为收尾必做步骤。

执行：

1. 先展示今日日记中 `## 明日计划` 的现状：
   - 若已有任务：`目前明天有以下任务：...`。
   - 若无任务：`目前明天还没有任务。`。
2. 使用固定提示向用户收口：
   - `请回复“否”，或直接告诉我明天有哪些任务。`
3. 分支处理：
   - 用户回复“否” -> 直接结束本次回顾。
   - 用户回复具体任务 -> 在今日日记 `## 明日计划` 区块追加写入。

## 输出标准

以下是完整日复盘的输出；仅取材按“Session 进度取材”报告草稿、覆盖范围与实际写入即可。

- 必须输出：
  - 今日回顾结论
  - 昨日计划完成度摘要（完成/部分完成/未完成/未核验）
  - 本周计划进展判断（按计划/部分偏离/明显偏离/未核验）
  - session 来源覆盖、时间边界及未核验项（跳过时说明仅依据日记）
  - 记录处理统计（转永久笔记/转任务/已处理/延期到 inbox）
  - 未完成任务去向统计（明天/本周/以后再说/取消）
  - 明日简计划结果（跳过/新增任务数量）
  - 已更新文件路径（今日日记 + `STATUS.md`）
- 若新增了明日任务，必须明确其写入位置为“今日日记 `## 明日计划`”。
- 若有延期，必须提示：`请在 /flownote-inbox 中批量处理`。

## 检查清单

适用于完整日复盘；仅取材使用其分支完成标准。

- [ ] 已读取今日日记并提取关键信息
- [ ] 已完成“昨日计划 vs 今日执行”对照（或明确无基线）
- [ ] 已完成本周计划进展检查（或明确无周基线）
- [ ] 已读取 `Meta/.ai-memory/STATUS.md` 相关区块
- [ ] 已完成记录去向处理或快速移交
- [ ] 已完成未完成任务去向安排
- [ ] 已完成明日简计划确认（用户“否”或已写入明日任务）
- [ ] 已先更新并校验日记，再最后同步并复读 `STATUS.md`
- [ ] 已输出可追溯总结
