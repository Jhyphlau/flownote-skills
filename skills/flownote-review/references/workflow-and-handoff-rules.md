# flownote-review 详细流程与移交规则

以下适用于完整日复盘；“今日/昨日/上周”相对用户指定的目标日期。仅 session 核对或补记按主 SKILL.md 的“Session 进度取材”结束，不进入本页全流程。

## 0) 先做基线对照（每日必做）

1. 读取昨日日记 `## 明日计划`（若存在）。
2. 按[主 Skill 的“对照任务”规则](../SKILL.md#session-进度取材)判断原任务完成范围，输出 `完成 / 部分完成 / 未完成 / 未核验`，并记录依据或缺失证据。
3. 读取上周周记 `## 下周计划`（若存在，作为本周计划基线），输出一句话周进展判断：`按计划推进 / 部分偏离 / 明显偏离 / 未核验`。
4. 若“部分偏离/明显偏离”，补 1 条“明日修正动作”候选并征求用户确认。

## 1) 记录处理优先级

候选限于记录区的个人思考。任务与任务进展用于执行核对；旧记录里的纯事实流水不自动制卡、移交或搬动。新增想法条目按主文件引用的 capture 时间规则写入，已有条目保留原时间。

1. 当天高价值记录优先（可转永久笔记）
2. 行动项次之（转任务）
3. 一般记录可标记已处理或延期

## 2) 延期移交规则（review -> inbox）

仅在完整日复盘中，按[主 Skill 的快速移交适用范围](../SKILL.md#快速移交模式时间不足)处理时间不足或中断：

1. 未处理记录统一标记 `⏭️ 待 /flownote-inbox`
2. 在当日总结中明确“延期数量”
3. 提示用户后续执行 `/flownote-inbox`

## 3) 未完成任务去向规则

未核验事项保留原状态，不自动视为未完成并安排去向。

- 明天做 -> 写今日日记 `## 明日计划`
- 本周做 -> 写 `Meta/.ai-memory/STATUS.md` 的“本周待处理”
- 以后再说 -> 写“以后再说”
- 已完成 -> 勾选
- 不做了 -> 标记取消

## 4) 明日简计划收尾规则

在每日回顾结束前，必须执行一次明日简计划确认：

1. 先展示今日日记 `## 明日计划` 现状（有则列出，无则明确“目前明天还没有任务”）。
2. 固定提示用户：`请回复“否”，或直接告诉我明天有哪些任务。`
3. 用户回复“否” -> 直接结束。
4. 用户给出具体任务 -> 若 `## 明日计划` 区块不存在，先补齐区块，再写入今日日记 `## 明日计划`。

## 5) 失败恢复

若更新日记或缓冲区失败：

1. 报告失败位置
2. 停止后续写入
3. 修复后继续

禁止静默失败。
