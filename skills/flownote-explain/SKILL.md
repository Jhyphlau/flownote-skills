# 概念解释（FLOWnote 轻适配）

直接帮助用户建立初步理解，用户无需先解释、选模型或完成测验。默认用简短自然语言回答；用户要求详细时再展开，解释深度不等于学习训练。

## 解释方法

按当前疑惑组织，不机械输出四栏：
- 先用普通话说明是什么，以及与最容易混淆的对象差在哪里；用途或比喻不能替代定义边界。
- 用必要的例子说明怎样起作用：技术对象讲输入、动作与结果；制度或角色讲参与者、规则与后果。例子区分事实与假想，不虚构人物动机。
- 从已经讲清的机制指出容易误解之处；有助于理解时给一个一般判断抓手。不强求认知反转、行动建议或长文。
- 解释达到用户要求即可结束。Agent 讲清楚不代表用户已掌握，不要求用户复述来换取答案。

## 知识库关联（按需）

已有对话材料够用就直接解释。用户要求结合已有记录，或相关材料能实质帮助理解当前概念时，复用 `obsidian-cli` 的检索能力，在永久笔记、`00-Inbox` 和 `01-捕获层` 中定向查找；只读相关片段，不把全库检索作为必经步骤。

永久笔记是已加工观点，不自动等于客观事实；Inbox 原文与捕获层初步记录保持各自来源性质。仅在实际找到强相关内容后给简短链接与关联理由，可提示用户选择结合它深入；未找到或工具不可用时如实说明，不虚构笔记，不阻塞一般解释。

## 委派与结束

`flownote` 负责知识业务意图路由，本 Skill 不自行开启另一条业务流程：
- 用户只是问“讲讲 X”，先解释；仅当歧义会改变任务时问一次。
- 用户要检验理解、练习或分析具体选择时，将该请求交还 `flownote` 或原 owner，由其委派 `flownote-think`；一般使用条件的解释不等于替用户作具体决策。
- 用户说“结合这段再讲讲”或展开相关笔记以理解当前概念时，仍在本 Skill 内只读解释，不因出现材料链接就启动阅读整理。材料是概念解释的参考，不顺手分析整篇。
- 用户目标转为读懂或整理材料本身（作者的问题、论证、证据与局限）时，由 `flownote` 或原 owner 交给 `flownote-read`，由它判断是否委派 `flownote-paper`。按概念还是材料为中心区分，不按回答长短区分。
- 阅读或思考中临时问词，只返回解释给原 owner，保留原任务，不借机开测验。
- 本 Skill 只读、只在对话中交付，不保存笔记、不更新进度或 STATUS，不固定追加“是否保存”。用户明确要求记录或制卡，由 `flownote` 或原 owner 按既有流程处理。

用户不需要看到 Skill 名称或委派链。发现可深入的方向不等于用户同意深入。

## 适配边界

采用上游 v5 的“定义边界—运作机制—认识变化—一般使用判断”；来源与固定版本记载在原分发仓库的 `SOURCES.md`，不是安装到 Vault 后的运行依赖。FLOWnote 保留轻量回答、按需关联与原任务归属；省去 Org、固定章节/段落、作者路径、Bun 校验和默认保存。旧版目标提炼及本地苏格拉底试验不在本 Skill 中恢复。
