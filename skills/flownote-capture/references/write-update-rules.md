# flownote-capture 写入与更新规则

## 1) 今日日记文件

目标文件：`01-捕获层/每日笔记/{{YYYY-MM-DD}}.md`

约束：想法落在 `## 记录`，执行事实落在 `## 任务进展`，待办落在 `## 任务` / `## 明日计划`；纯生活事件可写 `## 晚间回顾`，不额外建分类层。

若不存在：

1. 按 `../../flownote-note/assets/每日笔记模板.md` 创建六章节结构，以目标日展开日期和星期；不仿制旧日记。
2. 确认必要时间与权限后才创建和写入；条件不足则停留在草稿。

若已存在旧版区块，按下表识别同义章节，沿用原章节，不因本次写入自动重命名或迁移：

| 旧标题 | 标准标题 |
|---|---|
| `## ⭐ 今天最重要的事`、`## 🌅 今日计划` | `## 今天最重要的事` |
| `## ✅ 任务` | `## 任务` |
| `## 📝 记录`、`## 📝 今日记录` | `## 记录` |
| `## 🌙 晚间回顾` | `## 晚间回顾` |
| `## 📅 明日计划` | `## 明日计划` |

已有正文和条目原位保留。目标章节不存在时只增补必要章节；历史记录混杂不在本流程自动处理。

## 2) 记录区写入

仅个人想法、疑问、灵感与感受写入 `## 记录`：

```markdown
- {{HH:mm}} {{用户原话}}
```

规则：

- 语音输入仅去除语气词（嗯、啊、那个）
- 保留原话，不重写观点
- 每个新增顶层记录条目必须以有效的 `- HH:mm ` 开头，续行缩进保留在同一条目内；标题与模板说明不是记录条目。
- 写前取得可信时间：即时捕获取系统时钟并转换到 Asia/Shanghai；补录优先使用用户提供或材料可核验的原始时间。原时间未知时，可用真实录入时间但明确标注“补录，原时间未知”；写到历史日记时还须注明完整补录日期，不能冒充历史发生时间。
- 可信时间不可得或待写条目缺少/含无效时间戳时，拒绝该条写入，保留草稿并核实时间；不填 `00:00` 等占位时间，不先落盘再补。写后复读是额外核验，不替代写前检查。
- 既有记录只追加处理标记时保留原时间；不批量补造旧记录时间。此约束是 Agent 行为规则，不是文件系统硬拦截。

任务进展写入 `## 任务进展`，保留完成范围、必要时间与依据；已知时间可同样用 `- HH:mm 内容`，未知时间如实说明。时间戳不决定内容归属。

## 3) 新任务写入

写入到 `## 任务`：

```markdown
- [ ] {{任务内容}}
```

规则：

- 去掉“帮我加个任务”等提示词，仅保留任务正文
- 不擅自补截止日期

## 4) 明日计划写入

写入到 `## 明日计划`：

```markdown
- [ ] {{任务内容}}
```

规则：

- 仅在用户明确“明天/明日/明早”语义时写入该区块
- 与 `## 任务` 分开维护，避免混入今日执行清单

## 5) 任务完成更新

在 `## 任务` 中匹配待办项并更新：

```markdown
- [ ] 需求文档初稿
```

更新为：

```markdown
- [x] 需求文档初稿
```

匹配策略：

1. 精确匹配
2. 包含匹配
3. 语义近似匹配

若有多个候选，列出序号让用户确认。

若无候选，且用户已明确要记录、对象清楚，将事实写入 `## 任务进展` 并说明未勾选或新建任务；仅对象不清时核实一次。部分完成不勾选整体任务。混合表达的个人思考仍按记录区规则保存，不因完成事实丢掉后半句。

## 6) 写入后校验

每次写入后必须校验：

- 新建日记六个标准标题存在；已有日记目标章节正确、原有正文保留
- 新增记录条目都有有效时间戳，进展未混入记录区
- 新条目已落盘
- 返回内容与写入内容一致

## 7) 内容校验与确认

写入完成后、回复用户前检查：

1. 可一步纠正的事实错误：给出正确表述和依据。
2. 从数量、相关性或单一案例直接推出“必然结果”：标记为逻辑跳跃。
3. 含“只要/一定/必然/都/永远”等词但未提供机制、适用条件或反例边界：标记为待验证命题。

确认消息中的纠偏不改写已落盘原话。快速捕获只给最小纠偏，不自动进入费曼流程。

## 8) 错误恢复

若写入失败：

1. 重读文件并重试一次
2. 仍失败则报告失败原因
3. 不做静默失败
