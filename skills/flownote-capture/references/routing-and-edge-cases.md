# flownote-capture 路由判定与边界场景

## 1) 路由判定顺序

先拆辨语义，再按主文件的路由顺序处理；混合输入不因命中一个分支就忽略其余内容。

1. 待办：明确明日安排进 `## 明日计划`，今日任务进 `## 任务`。
2. 执行事实：行动、结果、完成程度进 `## 任务进展`；有明确匹配且完整完成才勾选。
3. 个人思考：想法、疑问、灵感与感受进 `## 记录`，先满足 `write-update-rules.md` 的时间要求。
4. “完成不了，是不是方向错了”是疑问；“今天改完简历，才发现……”同时包含进展与思考。保留背景与原意，不按关键词机械匹配。
5. 纯生活事件可写 `## 晚间回顾`；实际归属有歧义才问，不默认所有其他输入都进记录区。

## 2) 单句歧义处理

仅在以下情况追问：

- 目标对象、去向或拆分影响原意，无法依据当前上下文判断
- 指定的写入去向明显与章节用途冲突
- 保存记录所需的可信时间无法取得

按实际缺项只问一句（时间、对象、候选任务或去向）；归属问题示例：

`这是想记下一个想法，还是补充今天的执行进展？`

任务不存在但报告对象清楚时，按授权保存进展并说明未更新任务，不重复追问保存授权。

## 3) 跨技能关键词处理

用户输入中出现“阅读/项目/卡片/复盘”等词时：

- 默认仍按捕获处理，不自动切技能。
- 可在确认后附加轻提示：`晚上可用 /flownote-review 或 /flownote-card 继续处理。`

## 4) 批量输入处理

批量输入示例：

```
- 想法A
- 想法B
- 想法C
```

处理规则：

- 同批即时输入可共用一次系统取时（分钟级）；历史材料按可核验时间分别处理，不抹平原时间。
- 若用户明确某条是明日事项，单条路由到 `## 明日计划`。
- 今日待办进 `## 任务`，执行事实进 `## 任务进展`，个人思考进 `## 记录`；时间不足的条目保留草稿，不假报整批完成。

## 5) 交互模式结束词

识别以下词结束本轮：

- 完成
- 结束
- 没有了
- 就这些

结束后输出本轮汇总，不继续追问。
